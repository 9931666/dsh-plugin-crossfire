# v0.2.0 — 开评前确认卡 + 每维度专家粒度

本版给针锋加上「**开始评审之前**先看一张设置确认卡」的一步，并让红队阵容可以按维度逐行配置（模型 / 角色 / 提示词）。状态机与「表态由人做」的边界不变；不传新参数时行为与 v0.1.6 逐字一致。

## 新增：`crossfire_plan_review`（第 0 步）

- 在 `crossfire_open` 之前弹一张 Markdown 卡，固定两张表：
  - **表 1 评审设置**：评审标题、来源、强度（每维专家数 / 复审上限 / 轮数 / Token）、维度、立场摘要、红队人数。
  - **表 2 红队阵容**：`# / 维度 / 专家 key / 模型 / 角色 / 提示词` 六列。
- 表下方给待验证正文（超过 1200 字截断并注明「完整正文随评审落盘」）与立场全文。
- 按钮：「**确定开始**」/「**仍需修改**」。改完再弹时顶部列「本次变更」；主持人没写变更点就如实标「（本次未标注具体变更）」。
- 该工具**不落盘、不拉专家**：确认前磁盘上不会出现一条空评审。

## 红队阵容可以按维度逐行配置

- `crossfire_plan_review` / `crossfire_open` 新增 `experts[]`：每行一位专家，可指定 `dimension` / `key` / `role` / `provider` / `model` / `prompt`。
- `crossfire_open` 把确认过的阵容落盘为 `CrossfireRecord.expertRoster`；`crossfire_attack` 与卡片「发起攻击」都**优先消费它**（复审轮同样保留，不会退回设置页旧阵容）。
- 匹配优先级：`dimension` → `key` → 顺序兜底。用户给专家改名字也不会配错行；没有 `dimension` 的老 roster 行为不变。

## 专家提示词（补充定位）

- `prompt` 进入 persona 的「评审者补充提示词」段，并在同段声明：**只放宽专长范围，不放宽只读 / 不产出方案 / 不迎合**；与硬约束冲突的部分视为无效。
- 空值（缺省 / 空串 / 纯空白）时 persona 与 v0.1.6 **逐字一致**。`review.ts` 的净化白名单、`rpc.ts` 的 persona 重建分支都已同步，避免"写盘读不回"或"查看原提示词少一段"。

## 安全性

- `crossfire_plan_review` 已加入红队专家的工具黑名单：专家不能自己开评/改设置。
- 确认卡只确认「怎么开评」；认定/驳回仍在评审卡上由人完成。

## 兼容性

- 不传 `experts` 时：确认卡按「每维一位」生成默认阵容；`crossfire_open` 不写 `expertRoster`，`crossfire_attack` 退回原有规划，行为与 v0.1.6 一致。
- 默认阵容借 `planExperts` 生成（与真正开打同一段逻辑），不会出现"卡上是一套、开打是另一套"。
